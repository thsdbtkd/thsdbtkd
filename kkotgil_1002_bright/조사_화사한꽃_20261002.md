## 2. 삼각형·텍스처 예산
- 모바일 WebAR 은 모델당 5만 삼각형 이하·Draco 압축 후 4 MB 이하를 흔히 목표로 함 — https://blog.neural4d.com/user-guide/polygon-count-for-3d-game-assets-printing-and-webar/
- PNG/JPEG 는 GPU 에 풀려 올라감: 4096² 는 밉맵 포함 약 90 MB, 2048² PNG 는 약 21 MiB. KTX2(Basis, ETC1S/UASTC)는 GPU 에서도 압축 유지돼 4~8배 절감 — https://www.donmccurdy.com/2024/02/11/web-texture-formats/ , https://www.khronos.org/ktx/
- glTF 에서 KTX2 는 KHR_texture_basisu 확장 — https://doc.babylonjs.com/features/featuresDeepDive/materials/using/ktx2Compression
- 지금 기준값: 서버 vr27n_D_bank 3.5만·mound_c 5.3만 삼각형, 샘플 A 6.5만 삼각형 + 텍스처 10장(최대 2048²).
- 제안 예산(배치 문서 확인 전 가안): 꽃둑 1개 = 삼각형 6만 이하(뒷면 복제 포함), 꽃 텍스처는 아틀라스 1장 1024²(KTX2 ETC1S) + 잎 512², 파일 3 MB 이하.

## 3. 빛 굽기 방법
- Blender Cycles 굽기: 결과 텍스처용 UV(겹치지 않게) → 이미지 텍스처 노드 선택 → 굽기 종류 Combined 또는 Diffuse(직접·간접·색 따로 선택) → 저장 — https://docs.blender.org/manual/en/latest/render/cycles/baking.html (본문은 목차만 열려 세부는 아래 글로 확인), https://www.3dtexturegenerator.com/blog/how-to-bake-textures-in-blender
- 웹용 라이트맵: 두 번째 UV(UV2)에 Combined/Diffuse 굽기 → PNG/JPG → KTX2 변환 → three.js MeshStandardMaterial.lightMap 에 연결. 장면당 4~8시간 걸린다는 경험치 — https://svilenkovic.com/3d/how-to-bake-lighting-for-web
- 정점색 굽기(지금 vr27n 방식과 같은 계열): Cycles Diffuse 를 정점색으로 굽고 GLB 로 내보냄. 용량·GPU 부담이 적지만 잔그림자 해상도는 정점 밀도에 묶임 — https://wonderlandengine.com/news/vertex-color-baked-lighting/
- glTF 내보내기 설정 — https://docs.blender.org/manual/en/5.0/addons/import_export/scene_gltf2.html
- 압축·줄이기 도구: gltf-transform (simplify, resize, ktx2 etc1s/uastc, draco/meshopt) — https://gltf-transform.dev/ , https://www.npmjs.com/package/@gltf-transform/cli
- 판단: 꽃 송이는 「텍스처 = 꽃잎 색 + 구운 따뜻한 빛·그늘(Combined, 해 방향 왼쪽 위 45°, 따뜻한 색온도)」를 한 장에 굽고 unlit 재질로 내보내면 에디터 조명과 무관하게 참고 사진 톤 유지. 잎은 조명 받는 재질 유지.

## 4. 다음 작업 순서(제안)
1) 후보 2~3개(작약 1 스캔·장미 1 저폴리) 내려받아 라이선스 기록 → 2) Blender 에서 송이 1천~3천 삼각형으로 줄이고 512² 텍스처에 색·노멀 굽기 → 3) 따뜻한 빛 Combined 굽기 → 4) 꽃둑 배치(지금 vr27n 송이 위치에 교체) → 5) gltf-transform 으로 KTX2·meshopt → 6) 같은 조명 렌더로 참고 사진과 비교.
- 이 클라우드 방에 Blender 가 없어서(설치 가능 여부 미확인) 2)~3)은 맥 쪽 또는 Blender 설치 후 진행.
